# 蓝牙调参协议

USART2 使用 9600 baud，底层为循环 RX DMA 和普通 TX DMA。协议层只处理
ASCII 方括号帧：以 `[` 开始、以 `]` 结束，不需要追加 `\r\n`。收到残缺帧
后再次遇到 `[` 会自动从新帧重新同步。

## 手机发给小车

教程小程序的滑杆帧格式为：

```text
[slider,名称,数值]
```

当前支持以下名称：

| 名称 | 修改内容 |
| --- | --- |
| `AngleKp` / `AngleKi` / `AngleKd` | 直立环 `kp/ki/kd` |
| `SpeedKp` / `SpeedKi` / `SpeedKd` | 速度环 `kp/ki/kd` |
| `TurnKp` / `TurnKi` / `TurnKd` | 转向环 `kp/ki/kd` |
| `Offset` | 电机死区补偿幅值；混合出左右轮命令后按每轮符号叠加 |
| `OffsetBand` | 死区补偿线性过渡带宽；0表示过零±Offset硬跳变（旧行为） |
| `PosKp` | 驻车位置环增益，(counts/s)/count；0关闭位置保持 |
| `BalanceTrim` | 本项目额外提供的目标平衡角修正，单位为度 |

例如：

```text
[slider,AngleKp,-18.5]
[slider,AngleKd,-0.8]
[slider,Offset,3]
[slider,BalanceTrim,-0.35]
```

数值支持正负号和普通小数，不支持科学计数法。协议只负责把合法值写入
对应参数；滑杆最小值、最大值和步距应在手机小程序中按调参阶段设置。

也可以在小程序中建立三个按键：

```text
[key,Start,down]
[key,Stop,down]
[key,Recover,down]
```

`up` 帧会被正常接收但不执行。上电校准完成后会自动进入 `BALANCING`；
`Stop` 仅在 `BALANCING` 有效并进入 `FALLEN` 停机状态，`Start` 和
`Recover` 都可在 `FALLEN` 中触发重新校准；协议层会把二者映射成同一个
内部START命令。最终状态合法性仍由整车状态机裁决。

## 电机与编码器安全点动

轮子架空并进入 `FALLEN` 后，可以分别点动左轮、右轮或双轮：

```text
[motor,L,150]
[motor,L,-150]
[motor,R,150]
[motor,R,-150]
[motor,B,150]
[motor,B,-150]
```

`L/R/B` 分别表示左轮、右轮和双轮。命令绝对值最大为 `150`，即15% PWM；
每条命令固定运行300ms后自动停止。`BALANCING`、`CALIBRATING` 和 `FAULT`
状态都会拒绝点动，点动过程中发送 `[key,Stop,down]` 可立即停止。

OLED 在 `FALLEN` 状态把原速度环、转向环两行临时替换为：

- `A/G`：加固定安装偏置后的绝对加速度角和去零偏俯仰角速度；
- `L/R`：最近一次300ms点动窗口的左右编码器累计计数。

状态文字在点动期间显示 `TST`，结束后回到 `FAL`。逻辑正向点动时，期望
对应轮的编码器累计计数也为正；否则应修正该侧编码器方向配置。

原教程摇杆帧已经接入：

```text
[joystick,LH,LV,RH,RV]
```

四轴都会被解析并限制在 `-100..100`，当前使用 `LV` 控制前后、`RH` 控制
左右，`LH/RV` 仅为协议兼容保留。中心 `±5` 为死区；`LV=±100` 对应
`±2500 counts/s`，`RH=±100` 对应 `∓180 deg/s`。转向反号是因为内部约定
左转为正、右转为负，而手机右推通常给出正 `RH`。一帧会同时更新速度和
转向目标；超过500ms未收到新的运动目标时，两者自动归零。

这里没有照搬教程的 `/25`：教程速度环与转向环的目标单位不同，本车必须
分别使用编码器 `counts/s` 和陀螺仪 `deg/s`。

## 小车发给手机

当前转向环诊断阶段固定发送三条曲线：

```text
[plot,校正后GZ/10,目标GZ/10,转向差分输出/100]
```

手机图中的颜色顺序为：

1. 红色：校正后偏航角速度除以10；例如图上 `5` 代表 `50 deg/s`；
2. 绿色：摇杆给出的目标偏航角速度除以10；例如图上 `5` 代表目标
   `50 deg/s`；
3. 蓝色：转向环差分电机命令除以100；例如图上 `2` 代表命令 `200`。

红绿两线可直接比较实际值与目标值，用于判断稳态误差、超调和松杆后的回零；
蓝线用于观察为实现该角速度实际用了多少差分输出，以及是否碰到 `±3` 的
转向输出限幅。

发送完全非阻塞：上一帧的 DMA 尚未结束时，本周期帧直接跳过，不会拖慢
控制环。上述缩放都只为让三种量能在同一张图上观察，不参与控制计算。
当前 9600 baud 下两路数据适合做低频趋势观察；需要更密的动态
曲线时，应同时提高 HC-04 和 USART2 的波特率，而不是在控制循环里等待
串口发送。

## 电脑二进制遥测与记录

电脑桥接脚本连接后会发送：

```text
[telemetry,binary]
```

小车随后停止发送文本 `plot`，改为每60ms发送一帧带 CRC16-CCITT 的50字节
二进制快照。退出脚本时会发送 `[telemetry,text]`，手机上位机因此仍保持
兼容。二进制帧以 `A5 5A` 开头，字节序为 little-endian：

| 偏移 | 内容 |
| --- | --- |
| 0..1 | 魔数 `A5 5A` |
| 2..7 | 类型、版本、总长度、状态、标志、保留 |
| 8..9 | 16位序号，用于统计漏帧 |
| 10..13 | MCU `HAL_GetTick()` 时间戳 |
| 14..末尾-3 | 类型对应的载荷 |
| 末尾-2..末尾-1 | CRC16-CCITT，初值 `FFFF` |

类型1包含 Pitch、加速度角、俯仰/偏航角速度、GZ零偏、左右/平均/差分编码器
速度、速度/角度/偏航目标、速度积分、平衡/转向输出和左右电机命令。角度与
角速度使用 `0.01` 单位，速度和电机命令使用整数单位，速度积分使用
`0.001 deg`。类型2在进入二进制模式及在线参数变化后发送一次，包含三环
PID、平衡角、死区补偿（幅值与过渡带宽，带宽为第20个浮点、追加在帧尾）
和全部主要限幅。

标志位bit5表示转向积分达到自身限幅。转向积分独立限制为 `±50`；行驶中
即使目标转向为0也保留该积分以学习左右轮增益差，只有纵向目标为0、实测
速度低于 `400 counts/s` 且GZ进入死区时才清空。

`Tools/GamepadBridge.py` 会把每次运行写入 `Logs/日期时间/`：

- `telemetry.csv`：同一行记录手柄原始量、整形后命令与小车快照；
- `parameters.json`：本次实测参数；
- `link-stats.json`：有效帧率、序号漏帧率、CRC错误和收到的字节数。

当前模块只确认了9600 baud透明串口，没有找到可核实的固件型号和 AT 改速
命令，因此固件不单方面提速。50字节/60ms约占833 byte/s，已经接近9600
baud链路的960 byte/s理论净载荷；后续若要记录200Hz角度环，必须先在模块
AT模式确认并修改模块波特率，再同步修改 USART2。
